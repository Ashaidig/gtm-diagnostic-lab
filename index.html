Demo 1 - The value that is always one step behind

Trigger evaluationReports show fewer conversions than the client's own records

What you were trying to do: count completed purchases, using the checkout events the site already sends.

Container tag: D1 - Purchase (step=purchase) - Custom Event checkout_step with condition DLV step equals purchase. This site pushes the same event name at every stage of the checkout and tells the stages apart with a step field. That is an extremely common pattern, and it is why the trigger has to read step at all.

Checkout - cart
Item B SKU-100290.00
Total90.00 USD
Walk the checkout one click at a time. After each click, read what GTM actually saw.
Broken build: every event carries the previous stage's data, because the event is pushed before the data. At Place order GTM still sees step = payment, so the purchase does not count. One click later, on View order details - something every customer does - GTM finally sees step = purchase and fires the conversion there, on the wrong action and with the order ID attached. The client's records show a sale; your report does not, and a conversion appears against a page view instead. Switch to the fixed build and walk it again: the conversion fires once, at the purchase, and nowhere else.

Demo 6 - The foreign auto-tracker

ListenersEvents nobody set up

What you were trying to do: audit which events already exist on the page, and decide whether the form_submit event you found is safe to build a conversion on.

Container tag: D6 - Foreign auto-tracker event. A script hardcoded into this page pushes form_submit for every form submission - events nobody configured in GTM. The toggle below is your pause test.

The variant that catches people out: the foreign event does not have to come from the site. Another Google tag sitting in the same container can generate form_submit automatically, and a Custom Event trigger built on that generic name will happily fire on it. The fingerprint is eventModel. in the payload - those parameters mean a Google tag wrote the event, not the site. Before building on any common event name, check whether something else on the page already produces it.
